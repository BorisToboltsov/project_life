# Инварианты

Контракты кодовой базы. У каждого — причина одной фразой и гейт, который ловит нарушение.
Новый контракт добавляется сюда только вместе с гейтом.

## I1. Видимый текст — только через `t()` и сразу на всех языках

Словари лежат в `frontend/src/i18n/`; эталон формы — `ru.ts`, остальные языки обязаны
повторять его ключи и подстановки. Литералы в JSX и в атрибутах `title`, `aria-label`,
`alt`, `placeholder`, `label` запрещены.

**Причина:** частично переведённый интерфейс хуже непереведённого, а найти пропуск глазами
нельзя.

**Гейт:** тип `Dictionary` (пропущенный ключ не компилируется); правило
`i18next/no-literal-string` в `frontend/.oxlintrc.json`; `src/i18n/i18n.guard.test.ts`.

## I2. Типы API на фронтенде генерируются, а не пишутся руками

`frontend/src/api/schema.d.ts` меняется только командой `make api-client`. Запросы идут
через клиент из `src/api/client.ts`.

**Причина:** схема бэкенда — единственный источник правды; рукописные типы расходятся с
ней молча.

**Гейт:** `make check-api-client` — заново генерирует типы и сравнивает с файлом в
репозитории.

## I3. Изменение модели идёт вместе с миграцией, миграция откатывается

Схема базы после `alembic upgrade head` обязана совпадать с моделями SQLAlchemy; у каждой
миграции рабочий `downgrade`.

**Причина:** расхождение схемы и моделей всплывает только на сервере, на живых данных.

**Гейт:** `backend/tests/guards/test_migrations.py`.

## I4. Версия одна на весь репозиторий

`backend/pyproject.toml` и `frontend/package.json` называют одну версию в формате
`<major>.<фаза>.<фикс>`, и для неё есть раздел в `CHANGELOG.md`. Версия меняется только
командой `make version V=…`.

**Причина:** бэкенд и фронтенд выкатываются вместе; разные номера делают отчёт об ошибке
бесполезным.

**Гейт:** `scripts/check_version.py` (`make check-version`).

## I5. Эндпоинт закрыт, пока явно не объявлен открытым

Каждый маршрут API относится ровно к одной группе: открытый (перечислен поимённо в гейте),
административный (под `/api/admin`, обычному пользователю — 403) или пользовательский
(без входа — 401). Пользовательский маршрут с идентификатором записи обязан отвечать на
чужую запись так же, как на несуществующую, — 404. Защита вешается на роутер в
`app.main`, а не на отдельные функции.

**Причина:** в приложении лежат данные о здоровье нескольких людей; забытая проверка на
одном эндпоинте открывает их всем.

**Гейт:** `backend/tests/guards/test_isolation.py` — обходит все маршруты приложения;
новый маршрут с идентификатором без сценария владения делает гейт красным.

## I6. Ошибка API — код, а не фраза

Бэкенд отвечает на отказ кодом из `ErrorCode` (`{"detail": "<код>"}`), текст для
пользователя подбирает фронтенд по ключу `errors.<код>`. Каждый код обязан иметь перевод.

**Причина:** фраза с сервера не переводится и привязывает интерфейс к формулировке.

**Гейт:** типы — раздел `errors` в `frontend/src/i18n/ru.ts` обязан покрывать все значения
`ErrorCode` из сгенерированной схемы; непереведённый код не компилируется.

## I7. Дата в интерфейсе — день, месяц, год

Дата вводится и показывается в порядке «день, месяц, год» на любом языке и независимо от
настроек браузера. Для ввода — `DateField` (одно поле вида `дд/мм/гггг` с календарём),
для вывода — функции из `frontend/src/lib/dates.ts`. Нативные поля даты (`type="date"` и
родственные) запрещены: порядок частей в них задаёт браузер.

**Причина:** запись «05/06» читается двояко, а в данных о здоровье перепутанная дата —
это неверная история.

**Гейт:** `frontend/src/lib/dates.guard.test.ts`.

## I8. Ключ пользовательской записи — UUIDv7 от клиента

Запись, которую создаёт пользователь (замер, позже — приём пищи, подход), получает ключ на
клиенте и сохраняется запросом `PUT /…/{id}`: повтор запроса заменяет ту же запись, а не
создаёт вторую. Сервер принимает только UUID версии 7 — тип `RecordId` в `app.schemas`.

**Причина:** запрос могут отправить дважды — после сбоя сети, а позже из офлайн-очереди;
дубль в данных о здоровье искажает графики и итоги.

**Гейт:** `backend/tests/guards/test_isolation.py` — для каждого маршрута с ключом записи
проверяет, что ключ другой версии отклоняется.
