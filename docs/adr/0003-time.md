# ADR 0003. Время: UTC, зона пользователя и локальная дата записи

Статус: принято, 2026-10-05. Реализация — фазы 1–2.

## Контекст

Дневник считает итог «за день», лекарства принимают «в 8:00». Пользователь путешествует и
меняет часовой пояс, а история при этом меняться не должна.

## Решение

- **Моменты времени** хранятся как `timestamptz` в UTC.
- **Зона пользователя** — имя IANA (`Europe/Moscow`) в профиле.
- **Дневниковая запись** (вес, приём пищи, тренировка) дополнительно хранит локальную
  дату — календарный день пользователя в момент события. Дату присылает клиент; итоги за
  день считаются по ней.
- **Расписания** (приём лекарств) хранят локальное время без зоны («08:00») и
  разворачиваются в зоне, в которой пользователь находится сейчас.

## Альтернативы

- **Только UTC, день вычисляется по зоне профиля.** Смена зоны переносит старые записи
  между днями и переписывает прошлые итоги.
- **Локальное время без UTC.** Нельзя упорядочить события из разных зон и сверить их с
  данными устройств.

## Последствия

- У дневниковых таблиц два поля времени; локальная дата не выводится из момента и не
  пересчитывается.
- «Принять в 8:00» после перелёта означает 8:00 по новому месту — так задумано.
