# ADR 0018. Блюдо как продукт с рецептом

Статус: принято, 2026-10-17.

## Контекст

Блюдо должно использовать поиск, порции и снимки дневника. Рецепт редактируется целиком;
пользователь выбрал единую форму, отдельную массу жидкостей и сохранение удалённых
ингредиентов по снимку.

## Решение

Рецепт хранится в JSONB у продукта: упорядоченные ингредиенты со снимками и вес готового.
Сервер пересчитывает состав на 100 г и атомарно сохраняет рецепт вместе с продуктом.
При сохранении доступные ингредиенты читаются из каталога, удалённые — из прежнего
рецепта этого блюда. Прислать собственный снимок нельзя. Для мл количество определяет
состав, отдельная масса в граммах — исходный вес. Выход блюда пользователь может изменить.
Необязательный нутриент известен только при наличии у всех ингредиентов.

Вложенное блюдо используется по сохранённому составу. Циклы запрещены; сохранения каталога
сериализуются транзакционной advisory-блокировкой PostgreSQL. Список ограничен ста
ингредиентами, количества и выход — действующим пределом 5000.

## Альтернативы

Отдельный каталог блюд потребовал бы дублировать поиск и дневник. Таблица ингредиентов
удобнее для запросов по связям, но текущая форма читает и заменяет рецепт целиком.
Автоматический пересчёт зависимых блюд менял бы сохранённые рецепты без участия автора.
Пошаговая форма скрывала бы ингредиенты при выборе выхода и порции.

## Последствия

Снимки увеличивают размер каталога; при росте числа рецептов понадобится отдельная загрузка
рецепта и более узкая блокировка. Откат миграции удаляет рецепты, сохраняя продукты и их
рассчитанный состав. Статистика остаётся отдельным шагом 0.9.1.
