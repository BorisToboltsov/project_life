# ADR 0005. Выкладка: сервер сам забирает образы

Статус: принято, 2026-10-05. Реализовано в 0.2.1.

## Контекст

Приложение живёт на одном сервере с публичным адресом. На том же сервере работает VPN
(WireGuard), который нельзя задевать. Репозиторий публичный, CI — в GitHub Actions.
Нужно, чтобы коммит в `main`, прошедший гейты, оказывался на сервере без ручных шагов.

## Решение

- **CI публикует, сервер забирает.** После всех гейтов задача `publish` собирает образы
  бэкенда и веб-сервера и кладёт их в GitHub Container Registry: тег `latest` и тег
  `<версия>-<коммит>`. На сервере таймер systemd каждые 5 минут запускает
  `life-update`: тот скачивает `latest` и, если образы изменились, перезапускает
  контейнеры.
- **У GitHub нет доступа к серверу.** Ни SSH-ключа, ни агента: связь только исходящая, с
  сервера в реестр.
- **Автоматически меняются только образы.** `compose.yaml`, скрипты и юниты systemd
  ставит и обновляет администратор командой `deploy/install.sh`. То, что пришло
  автоматически, работает в контейнерах без доступа к файлам и сети хоста.
- **Перед обновлением — бэкап.** Если база уже работает, `life-update` сначала делает
  шифрованный дамп. Не удался бэкап — обновление не выполняется.
- **Миграции накатывает отдельный контейнер** `migrate` до старта бэкенда.
- **Сетевой след минимален.** Наружу открыты только TCP 80 и 443; HTTP/3 выключен,
  UDP-порты приложение не занимает. Скрипты не трогают файрвол, маршрутизацию и
  настройки Docker.
- **Бэкапы шифруются открытым ключом `age`.** Закрытый ключ на сервере не хранится:
  взлом сервера не раскрывает прежние дампы.

## Альтернативы

- **Выкладка по SSH из GitHub Actions.** Проще и мгновенна, но ключ с правами на Docker
  (то есть фактически root) лежал бы в секретах GitHub: компрометация репозитория или
  workflow давала бы оболочку на сервере с VPN.
- **Свой раннер GitHub на сервере.** Для публичного репозитория опасен: код из чужого
  pull request может выполниться на сервере.
- **Watchtower.** Делает то же, что таймер, но это сторонний контейнер с доступом к
  сокету Docker; собственный скрипт на 40 строк короче и умеет бэкап перед обновлением.

## Последствия

- Новая версия появляется на сервере в пределах 5 минут после зелёного CI, а не сразу.
- Изменение `compose.yaml` или скриптов требует ручного шага на сервере.
- Откат — тег прежней сборки в `IMAGE_TAG`. Миграции назад не откатываются: если версия
  меняла схему, откат — это восстановление из бэкапа, сделанного перед обновлением.
- Образ `latest` в реестре — точка, через которую код попадает на сервер. Её защищают
  обязательные гейты перед публикацией и права на запись в `main`.
- Скрипты выкладки проверяет гейт `make check-deploy` — на Ubuntu 24.04, с настоящим
  реестром образов.
