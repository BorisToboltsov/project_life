# Архитектура

Карта устройства. Правила и запреты — в [INVARIANTS.md](INVARIANTS.md), причины крупных
выборов — в [adr/](adr/).

## Стек

| Слой | Технологии |
|------|------------|
| Бэкенд | Python 3.14, FastAPI, Pydantic v2, SQLAlchemy 2 (async, psycopg 3), Alembic |
| База | PostgreSQL 18 |
| Фронтенд | TypeScript, React 19, Vite, Tailwind CSS 4, shadcn/ui, TanStack Query и Router, i18next |
| PWA | vite-plugin-pwa (Workbox): манифест и service worker с предкэшем оболочки |
| Веб-сервер | Caddy: HTTPS, статика фронтенда, прокси `/api` на бэкенд |
| Инструменты | uv, ruff, pyright, pytest · pnpm, oxlint, prettier, vitest, Playwright |

## Граница фронтенда и бэкенда

Единственный канал — HTTP JSON API под префиксом `/api`. Контракт описывает OpenAPI,
который отдаёт сам бэкенд (`/api/openapi.json`, Swagger UI — `/api/docs`). Из него
генерируются типы фронтенда (`frontend/src/api/schema.d.ts`), запросы идут через
типизированный клиент `openapi-fetch`.

Фронтенд и API живут на одном origin: Caddy отдаёт статику и проксирует `/api/*`. CORS не
нужен.

## Контейнеры

Стенд описан в `deploy/compose.yaml`.

| Сервис | Образ | Роль |
|--------|-------|------|
| `db` | `postgres:18` | данные; том `db` |
| `migrate` | образ бэкенда | разово выполняет `alembic upgrade head` и завершается |
| `backend` | `backend/Dockerfile` | API на uvicorn; стартует после успешных миграций; порт наружу не публикуется |
| `web` | `frontend/Dockerfile` | Caddy со сборкой фронтенда; единственный сервис с открытыми портами |

Адрес сайта задаёт переменная `SITE_ADDRESS`: домен на сервере (сертификат Caddy получает
сам) или `:80` на стенде для e2e.

## Бэкенд

- `app.main` — фабрика приложения. Роутеры собраны в три группы: открытая, для вошедших
  и для администратора; защита вешается на группу целиком.
- `app.config` — настройки из окружения с префиксом `LIFE_`.
- `app.db` — движок, фабрика сессий, базовый класс моделей с соглашением об именах
  ограничений.
- `app.log` — логи одной JSON-строкой на запись, включая логи uvicorn.
- `app.errors` — коды ошибок API (`ErrorCode`) и исключение `ApiError`.
- `app.schemas` — схемы запросов и ответов вместе с ограничениями значений.
- `app.models` — модели SQLAlchemy.
- `app.metrics` — справочник показателей (вес, шея, талия, бёдра): величина, каноническая
  единица, допустимый диапазон; здесь же пересчёт единиц.
- `app.security` — хэши паролей (argon2id), JWT, случайные токены и их хэши.
- `app.services` — логика без HTTP: сессии с ротацией refresh-токена, ограничение частоты
  входа, одноразовые ссылки.
- `app.api` — роутеры и зависимости `current_user` / `require_admin`.
- `app.cli` — команды администратора сервера (`python -m app.cli invite --admin`).

### Эндпоинты

| Группа | Маршруты |
|--------|----------|
| Открытые | `GET /api/health`; `POST /api/auth/…`: `login`, `register`, `refresh`, `logout`, `invite/check`, `password-reset`, `password-reset/check` |
| Для вошедших | `GET` и `PATCH /api/me`; `POST /api/auth/password`, `POST /api/auth/logout-all`; `GET /api/metric-types`; `GET /api/measurements`, `GET /api/measurements/summary`, `PUT` и `DELETE /api/measurements/{id}` |
| Для администратора | `/api/admin/users`, `/api/admin/users/{id}/password-reset`, `/api/admin/invites`, `/api/admin/invites/{id}` |

### Таблицы

| Таблица | Что хранит |
|---------|------------|
| `users` | учётная запись и профиль: почта, хэш пароля, роль, язык, часовой пояс, единицы, пол, дата рождения, рост |
| `refresh_tokens` | хэши refresh-токенов; токены одного входа связаны семейством |
| `invites` | хэши ссылок-приглашений с ролью, сроком и отметкой об использовании |
| `password_resets` | хэши ссылок для сброса пароля |
| `login_failures` | неудачные попытки входа для ограничения частоты |
| `measurements` | измерения показателей: значение в канонической единице, исходное значение и единица, момент и местная дата, источник |

### Показатели

Все числовые показатели лежат в одной таблице `measurements` и различаются кодом из
справочника `app.metrics`. Клиент присылает значение и единицу, как их ввёл пользователь;
сервер пересчитывает в каноническую единицу и хранит оба значения
([ADR 0004](adr/0004-units.md)). Ключ записи выбирает клиент
([ADR 0002](adr/0002-record-ids.md)), местную дату — тоже ([ADR 0003](adr/0003-time.md)).

### Вход

Схема описана в [ADR 0001](adr/0001-auth-jwt.md). Access-JWT клиент шлёт в заголовке
`Authorization`; refresh-токен лежит в cookie, доступном только `/api/auth`, и меняется
при каждом обновлении.

## Фронтенд

- `src/main.tsx` — точка входа: провайдеры, регистрация service worker, старт сессии.
- `src/app/` — `App` (экраны загрузки и «нет связи»), дерево маршрутов с защитой
  (`router.tsx`), рамки `AuthLayout` и `AppShell`.
- `src/auth/` — сессия: access-токен в памяти, обновление одним общим запросом, выход.
- `src/api/` — сгенерированные типы и клиент; клиент сам подставляет токен и повторяет
  запрос после его обновления.
- `src/i18n/` — словари и выбор языка: до входа — язык браузера или сохранённый выбор,
  после входа — язык из профиля.
- `src/lib/` — пересчёт единиц, разбор и формат чисел и дат, линия тренда, генерация
  UUIDv7, сопоставление ошибок API ключам словаря.
- `src/components/ui/` — компоненты shadcn/ui, добавляются из реестра как есть.
- `src/components/form/` — поля форм с подписью, подсказкой и ошибкой, поле даты.
- `src/components/illustrations/` — анимированные SVG-подсказки «как измерять».
- `src/components/chart/` — линейный график на ECharts; подгружается отдельным куском
  сборки при первом показе.
- `src/pages/` — экраны: `auth/` (вход, приглашение, сброс), `measurements/` (ввод,
  история с графиком, правка), `profile/`, `admin/`.

Маршруты делятся на гостевые (`/login`, `/invite`, `/reset`) и приложение (`/`,
`/measurements/…`, `/profile`, `/admin`). Проверка на маршруте — удобство, а не защита: данные закрывает
бэкенд.

Кэш запросов (TanStack Query) принадлежит одному пользователю и очищается при смене
вошедшего.
