# Разбор ошибок

Симптом → причина → что делать. Как ставить и обновлять — в [INSTALL.md](INSTALL.md).

Общее для сервера: состояние контейнеров — `cd /opt/life && docker compose ps`, логи —
`docker compose logs --tail 100 <сервис>` (`db`, `migrate`, `backend`, `web`).

## Сайт не открывается или браузер ругается на сертификат

**Причина.** Caddy получает сертификат при первом обращении к домену. Для этого домен
должен указывать на сервер, а порты 80 и 443 — быть доступны из интернета.

**Что делать.**

- `dig +short <домен>` — должен вернуть адрес сервера.
- `sudo ss -ltnp 'sport = :80'` и то же для `:443` — слушать должен `docker-proxy`.
- Если включён `ufw`: `sudo ufw allow 80,443/tcp`. Проверьте и файрвол у хостера.
- `docker compose logs web` — Caddy пишет, на чём остановилось получение сертификата.

## Установщик говорит «порт 80 уже занят»

**Причина.** На сервере уже работает веб-сервер (nginx, Apache) или другой контейнер.

**Что делать.** Посмотрите, кто слушает порт: `sudo ss -ltnp 'sport = :80'`. Освободите
порт либо поставьте приложение за существующий веб-сервер — тогда перед установкой
задайте другие порты (`HTTP_PORT=8080 HTTPS_PORT=8443 bash install.sh …`) и настройте
проксирование сами.

## После установки Docker перестал работать VPN

**Причина.** Docker переключил политику цепочки `FORWARD` в `DROP`, и сервер перестал
пересылать пакеты VPN-клиентов.

**Что делать.**

- Проверить: `sudo iptables -S FORWARD | head -1` — `-P FORWARD DROP` подтверждает причину.
- Вернуть сразу: `sudo iptables -P FORWARD ACCEPT`.
- Закрепить: в `/etc/docker/daemon.json` добавить `"ip-forward-no-drop": true` и
  перезапустить Docker (`sudo systemctl restart docker`).

## Новая версия не появляется на сервере

**Причина.** Сервер обновляется только по команде. Если команду запускали, то либо CI не
опубликовал образы, либо обновление завершилось ошибкой.

**Что делать.**

- На сервере: `sudo /opt/life/bin/life-update` — скрипт пишет, что делает и на чём
  остановился.
- На GitHub: у коммита в `main` задача «Публикация образов» должна быть зелёной.
- «pull access denied» — пакеты в GitHub закрыты: откройте страницу каждого пакета →
  Package settings → Change visibility → Public.
- Ошибка бэкапа — см. следующий раздел: без бэкапа обновление не выполняется.

## Бэкап не делается

**Причина и что делать.**

- «не задан BACKUP_RECIPIENT» — впишите открытый ключ `age1…` в `/opt/life/.env`.
- «age: command not found» — `sudo apt-get install -y age`.
- Ошибка `rclone` — хранилище из `BACKUP_REMOTE` недоступно; локальный файл при этом уже
  создан. Проверьте `rclone lsd <хранилище>:`.

## После обновления приложение не запускается

**Причина.** Чаще всего — миграция не прошла на живых данных.

**Что делать.**

- `docker compose logs migrate` — текст ошибки миграции.
- Вернуть прежнюю версию: в `.env` задать `IMAGE_TAG` прежней сборки, запустить
  `life-update`. Если миграция успела частично изменить схему — восстановить базу из
  бэкапа с меткой `pre-update` (см. INSTALL.md, «Восстановление»).

## Бэкенд не стартует: «LIFE_JWT_SECRET обязан быть задан»

**Причина.** В `.env` нет `JWT_SECRET` или он короче 32 символов.

**Что делать.** Сгенерировать новый: `openssl rand -hex 32`, вписать в `.env`, выполнить
`docker compose up -d`. Все пользователи выйдут из приложения и войдут заново.

## Локально: тесты бэкенда не подключаются к базе

**Причина.** Не запущена база разработки.

**Что делать.** `make db`. Тесты ждут её на `localhost:5433`.

## Локально: `make e2e` падает на получении ссылки администратора

**Причина.** Стенд не поднялся, и команда в контейнере бэкенда не выполнилась.

**Что делать.** `make stand`, затем `docker compose -p life-e2e ps` и логи упавшего
сервиса.
