# Установка на сервер

Как поставить приложение на свой сервер, как оно обновляется и как устроены бэкапы.
Почему выкладка устроена именно так — в [ADR 0005](adr/0005-deployment.md); что делать,
если что-то пошло не так, — в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Что окажется на сервере

| Где | Что |
|-----|-----|
| `/opt/life/compose.yaml` | описание контейнеров |
| `/opt/life/.env` | настройки и секреты; доступен только root |
| `/opt/life/bin/` | `life-update` и `life-backup` |
| `/opt/life/backups/` | шифрованные дампы базы; доступен только root |
| `/opt/life/src/` | клон репозитория — из него ставятся файлы выше |
| `/etc/systemd/system/life-backup.*` | таймер ежедневного бэкапа |
| тома Docker `life_db`, `life_caddy_data`, `life_caddy_config` | база и сертификаты |

Работают три контейнера: PostgreSQL, бэкенд и Caddy. В покое они занимают около 130 МБ
памяти; образы — около 800 МБ диска.

## Что нужно

- Ubuntu 24.04, доступ root.
- Домен с A-записью на адрес сервера.
- Свободные и открытые снаружи порты **TCP 80 и 443**. UDP-порты приложение не занимает.
- Не меньше 512 МБ свободной памяти и 3 ГБ диска. На сервере с 1 ГБ памяти полезен файл
  подкачки.
- Исходящий HTTPS до `world.openfoodfacts.org` и `search.openfoodfacts.org` — для поиска
  продуктов по штрихкоду и по названию. Без него сканер и поиск находят только то, что
  уже есть в своём каталоге.

## Если на сервере есть VPN или другая маршрутизация

Сам установщик не трогает ни файрвол, ни маршрутизацию, ни настройки Docker. Задеть VPN
может установка Docker — её вы делаете сами, поэтому сначала прочтите этот раздел.

1. **Правило пересылки.** При старте Docker может переключить политику цепочки `FORWARD`
   в `DROP`, и сервер перестанет пересылать пакеты VPN-клиентов. Чтобы этого не случилось,
   **до установки Docker** создайте `/etc/docker/daemon.json`:

   ```json
   { "ip-forward-no-drop": true }
   ```

2. **Подсети.** Docker берёт сети из `172.17.0.0/16` и соседних. Если VPN использует
   адреса из `172.16.0.0/12`, добавьте в тот же файл свой диапазон, например:

   ```json
   {
     "ip-forward-no-drop": true,
     "default-address-pools": [{ "base": "10.210.0.0/16", "size": 24 }]
   }
   ```

3. **Docker уже установлен.** Параметр `ip-forward-no-drop` понимает Docker 28 и новее
   (`docker --version`); более старый с незнакомым параметром не запустится. Изменение
   `daemon.json` вступает в силу после `systemctl restart docker`, а перезапуск
   останавливает все контейнеры: если VPN сам работает в контейнере, он на это время
   отключится.

4. **Проверка.** После установки Docker и после установки приложения подключитесь к VPN с
   клиента и убедитесь, что интернет через него работает.

## Шаг 1. Ключ для бэкапов — на своём компьютере

Бэкапы шифруются открытым ключом, а читаются только закрытым. Закрытый ключ на сервер не
попадает.

```bash
brew install age
```

```bash
age-keygen -o life-backup.key
```

Команда напечатает открытый ключ (`age1…`) — он понадобится на шаге 3. Файл
`life-backup.key` сохраните в менеджере паролей: **без него бэкапы не прочитать.**

## Шаг 2. Подготовка сервера

Всё нужное есть в репозитории Ubuntu. Если на сервере работает VPN — сначала раздел выше:
`daemon.json` должен появиться до установки Docker.

```bash
sudo apt-get update
```

```bash
sudo apt-get install -y docker.io docker-compose-v2 age git
```

Если включён `ufw`, откройте порты:

```bash
sudo ufw allow 80,443/tcp
```

## Шаг 3. Установка

```bash
sudo git clone https://github.com/BorisToboltsov/project_life /opt/life/src
```

```bash
sudo bash /opt/life/src/deploy/install.sh life.example.com age1…
```

Первый аргумент — домен, второй — открытый ключ из шага 1. Установщик создаст `.env` с
секретами (они генерируются на сервере и никуда не передаются), скачает образы, запустит
контейнеры и включит таймер бэкапа. Сертификат Caddy получит сам при первом обращении к домену.

**Поиск в Open Food Facts.** Продукт, которого нет в своём каталоге, сервер ищет в Open
Food Facts: по штрихкоду — сам, по названию — когда человек нажал «Искать в Open Food
Facts». Наружу при этом уходит только штрихкод или текст поиска. Чтобы сервер не
обращался наружу вовсе, добавьте в `/opt/life/.env` строку `OFF_URL=` (с пустым
значением); чтобы выключить только поиск по названию — строку `OFF_SEARCH_URL=`. Затем
перезапустите контейнеры: `cd /opt/life && sudo docker compose up -d`. Настройки читает
`compose.yaml`: на сервере, поставленном до версии 0.4.2, сначала обновите файлы сервера
(см. «Обновление»).

## Шаг 4. Первый администратор

```bash
cd /opt/life && sudo docker compose exec backend python -m app.cli invite --admin
```

Команда печатает ссылку; откройте её и зарегистрируйтесь. Остальных приглашаете уже из
приложения — см. [GUIDE.md](GUIDE.md).

## Обновление

**Приложение обновляется вручную.** Слияние в `main` и зелёный CI публикуют новые образы,
но на сервер они попадают только по команде:

```bash
sudo /opt/life/bin/life-update
```

Скрипт скачивает образы; если они новее работающих, делает бэкап базы и перезапускает
контейнеры. Если обновлять нечего, он так и скажет. У тех, у кого приложение открыто,
появится строка «Доступна новая версия» — новая версия включается, когда её нажмут. Какая
версия работает сейчас:

```bash
curl -s https://life.example.com/api/health
```

**Переход с 0.12 на 0.13.** Обновите файлы сервера и повторно запустите установщик:
он добавит Garage, его тома и ключи. Одного `life-update` со старым compose недостаточно.

**Файлы сервера** — `compose.yaml`, скрипты, таймеры — обновляются только вручную:

```bash
sudo git -C /opt/life/src pull
```

```bash
sudo bash /opt/life/src/deploy/install.sh
```

Секреты в `.env` повторная установка не трогает. Заодно она скачивает свежие образы, то
есть обновляет и само приложение.

**Откат.** В `/opt/life/.env` замените `IMAGE_TAG=latest` на тег прежней сборки вида
`0.2.0-1a4e002` (список — на странице пакета в GitHub) и запустите `life-update`. Так же
ставится любая конкретная версия вместо последней.
Миграции назад не откатываются: если новая версия меняла схему базы, после смены тега
восстановите базу из бэкапа с меткой `pre-update`.

## Бэкапы

С 0.13.0 `life-backup` создаёт комплект в `/opt/life/backups/files/<UTC>-<метка>/`:
зашифрованные `database.sql.gz.age`, `manifest.json.age`, индекс `references.json` и
маркер `complete`. Общие зашифрованные объекты лежат в `files/objects/`; копировать
один каталог комплекта без них недостаточно. Метки: `daily`, `preupdate`, `manual`.

На время копирования изменения вложений и очистка приостанавливаются; числовые записи
работают. Бэкап содержит состояние базы на один момент времени. В 0.13.0 новые комплекты
**не удаляются автоматически**: `BACKUP_KEEP_DAYS` относится только к старым SQL-бэкапам
до 0.13. Следите за свободным местом. Не удаляйте общие объекты вручную: один объект
может использоваться несколькими комплектами.

| Что | Команда |
|-----|---------|
| Сделать бэкап сейчас | `sudo /opt/life/bin/life-backup` |
| Журнал бэкапов | `journalctl -u life-backup` |

**Копия вне сервера.** Настройте `rclone` и `BACKUP_REMOTE=backup:life` в `.env`.
Объекты копируются первыми, маркеры complete — последними. Неудача внешнего переноса
завершает команду с ошибкой. Для проверки наличия копии проверяйте и журнал команды.

**Восстановление 0.13+.** Сначала проверьте восстановление на отдельном компьютере или
пустом сервере с той же версией приложения. Скопируйте всё дерево `backups/files`,
подготовьте `.env` и контейнеры PostgreSQL/Garage обычной установкой. Закрытый age-ключ
нужен только оператору восстановления; штатный бэкап по-прежнему использует открытый.
Для временных расшифрованных файлов нужен свободный диск размером с дамп и оригиналы.

Остановите приложение и очистку. Укажите существующий комплект и абсолютный путь к
закрытому ключу на машине восстановления:

```bash
cd /opt/life
docker compose stop web backend file-cleanup imaging-worker
docker compose run --rm -T --no-deps --user 0 \
  -v "$PWD/backups:/backups:ro" \
  -v /absolute/private/life-backup.key:/run/identity:ro \
  backend python -m app.file_backup restore \
  --bundle /backups/files/20261020T033000000000Z-daily --identity /run/identity
```

Команда сначала проверяет все хэши, затем восстанавливает объекты и базу. При ошибке
приложение остаётся остановленным: устраните причину и повторите. Незавершённые загрузки
переходят в failed. После успеха запустите сервисы и откройте/скачайте тестовый оригинал:

```bash
docker compose start backend file-cleanup imaging-worker web
```

Повторяйте проверку восстановления раз в квартал. Для старого бэкапа до 0.13 достаточно
расшифровать SQL командой `age -d -i life-backup.key old.sql.gz.age | gunzip`, восстановить
через `psql --set ON_ERROR_STOP=1` при остановленном приложении и применить миграции.
Старый SQL-бэкап не содержит файлов.

## Хранилище файлов

Установщик создаёт `STORAGE_KEY`/`STORAGE_SECRET` и сохраняет их при повторном запуске.
Garage хранит данные в Docker-томе `storage_data`, конфигурацию — в `storage_config`.
Порт S3 наружу не публикуется. Дополнительное место требуется для оригиналов,
временных загрузок и зашифрованных бэкапов; на локальном стенде используйте `make stand`.

## Удаление

```bash
sudo systemctl disable --now life-backup.timer
```

```bash
cd /opt/life && sudo docker compose down
```

Данные остаются в томах Docker. `docker compose down --volumes` удалит и их — вместе с
базой.

### Обработчик исследований

`imaging-worker` запускается после миграций и подготовки Garage. Для него выделены
1 CPU и до 2 ГБ памяти; временное распаковывание использует диск контейнера `/scratch`,
а не RAM. Для архива предельного размера требуется около 11 ГБ свободного диска сверх
места постоянного хранения. Остатки временных файлов после аварийной остановки удаляются
при старте этого контейнера. Внутренняя сеть соединяет обработчик только с БД и Garage.
Для локальной разработки после `make storage` запустите из `backend`:
`uv run python -m app.imaging.queue`.

### Ресурсы просмотра DICOM

Помимо места для импорта, контейнеру API требуется временный диск для двух
экземпляров DICOM одновременно и запас RAM для двух процессов декодирования.
Лимиты процессов и кадров приведены в [архитектуре](ARCHITECTURE.md).
Кодеки уже включены в backend-образ; отдельная установка на хосте не требуется.
Бинарные ответы и оригиналы идут через Caddy; proxy не должен кэшировать `/api/`.
