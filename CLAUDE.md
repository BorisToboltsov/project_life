# CLAUDE.md — правила разработки project_life

Свод **обязательных правил** для любой работы в этом репозитории. Файл загружается в
начале каждой сессии — держи его компактным: сюда только то, что нужно соблюдать,
подробности живут в `docs/`.

---

## Начало работы

Проверяй, в какой мы ветке. Начиная новую задачу, обнови `main` и создай от него новую
ветку — в ней идёт работа над одной задачей или списком задач. Название придумывай по
задаче или по списку (например, `phase-0/dev-scaffold`).

## Definition of Done (каждая задача)

1. **Тесты обязательны.** На каждую фичу и фикс — тесты. Новый контракт закрепляй гейтом и
   **проверяй его на живом нарушении**, а не только на зелёном коде. Гейты лежат так:
   фронтенд — `*.guard.test.ts`, бэкенд — `backend/tests/guards/`, уровень репозитория —
   `scripts/check_*.py` с целью `make check-*`.
2. **Гейты зелёные.** По ходу работы гоняй затронутые (команды ниже); **перед завершением
   фазы — полный прогон целиком**. Красное — чини, не обходи.
3. **Документация наравне с кодом.** Пройди по «Карте документации» выше и обнови **каждый**
   файл, чей жанр задет: минимум — CHANGELOG (что изменилось) и ROADMAP (статус фазы), плюс
   INVARIANTS, если появился контракт. Фича без отражения в доках — **незавершённая**.
4. **Перевод наравне с кодом.** Любой видимый текст — только через `t()` и **сразу на всех**
   языках (см. ниже). Частичный перевод не компилируется.
5. **Версия** поднята согласованно (см. «Версионирование»).

### Полный прогон

```bash
make check
```

Нужен запущенный Docker. Части прогона по отдельности:

| Цель | Что проверяет |
|------|---------------|
| `make check-version` | версия в манифестах и CHANGELOG |
| `make check-backend` | ruff, pyright, pytest на реальном PostgreSQL, покрытие ≥ 85 % |
| `make check-api-client` | типы API на фронтенде совпадают с бэкендом |
| `make check-frontend` | prettier, oxlint, tsc, vitest с покрытием ≥ 70 %, сборка |
| `make e2e` | сквозной смоук против собранного стенда |

Пороги покрытия не снижаются. Подробности набора — в [docs/TESTS.md](docs/TESTS.md).

### Очистка после зелёного прогона

```bash
make clean
```

Гасит стенд e2e вместе с его томами и удаляет отчёты и кэши прогона. База разработки
(`make db`) остаётся.

## i18n — ЗАКРЕПЛЕНО

- **Языки:** русский и английский. Словари — `frontend/src/i18n/ru.ts` (эталон формы) и
  `en.ts`.
- **Главное правило.** Весь видимый текст — на **всех** языках, через `t()`. Хардкод строк
  запрещён (надписи, кнопки, `title`/`aria-label`, тосты, тексты ошибок). Ключ добавляется
  **сразу во все** словари.
- **Логику не завязывай на перевод:** храни в состоянии и в базе канонические коды,
  локализуй при выводе. Бэкенд отдаёт коды ошибок, а не готовые фразы.

## Версионирование

Схема `<major>.<фаза>.<фикс>`: вторая цифра — номер фазы из
[docs/ROADMAP.md](docs/ROADMAP.md) (растёт на новой фазе, третья сбрасывается в 0),
третья — фикс внутри фазы. `major` поднимается только на публичном рубеже; до него
разработка идёт на `0.<фаза>.<фикс>`. Пререлизных суффиксов нет.

Версия записана в `backend/pyproject.toml` и `frontend/package.json` и правится **только**
одной командой:

```bash
make version V=0.1.0
```

Вместе с версией добавь раздел `## <версия>` в CHANGELOG — без него гейт не пройдёт.

## Toolchain

Python 3.14 и `uv`, Node 24 и `pnpm`, Docker с Compose, `make`.

```bash
make install        # зависимости и браузер для e2e
make db             # PostgreSQL для разработки на localhost:5433
make dev-backend    # бэкенд на :8000 с автоперезагрузкой
make dev-frontend   # фронтенд на :5173, /api проксируется на бэкенд
make api-client     # перегенерировать типы API после изменения эндпоинтов
```

Новая миграция: `cd backend && uv run alembic revision --autogenerate -m "описание"`.

## Сборка

Образы собираются из `backend/Dockerfile` и `frontend/Dockerfile` (Caddy со статикой
фронтенда). Стенд целиком описан в `deploy/compose.yaml`:

```bash
make stand          # собрать и поднять стенд на http://localhost:8080
make stand-down     # погасить его вместе с данными
```

Выкладка на сервер появится вместе с сервером — см. фазу 0 в ROADMAP.
